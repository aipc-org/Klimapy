# 常见问题与故障排查

## 安装后找不到 Rust 引擎

先检查版本、实际导入路径和 `backend_info()`。使用对应平台的原生 wheel；源码构建需要 Cargo，不能依靠 Python 数值回退继续运行。不要将其他平台的二进制直接复制过来。

## 无法加载 NetCDF 运行库

安装系统 libnetcdf / HDF5，并检查动态库搜索路径。Windows 还需检查 NetCDF DLL 的依赖是否齐全；可用 `KLIMAPY_NETCDF_LIBRARY` 明确指定路径。此错误与是否安装 xarray 无关。

## 旧版 xarray 示例为什么报错

1.1.0 将高层对象统一为 Field；批量指标返回字典，不能再直接对整个字典调用 `to_netcdf`。应取出具体指标字段写出。详细变化见[迁移说明](migration.html)。

## 结果为什么是 NaN

核对全年或月度有效天数是否达到 `min_valid_fraction`，单位是否正确，以及目标网格是否位于源网格支持范围内。全缺失点不会填零；普通插值区域外不外推。百分位指标还需要足够的基准期样本。

## 百分位指标为什么与别的软件不同

检查湿日阈值、分位数类型、日序窗口、基准年份、温度 bootstrap、闰日处理和覆盖率是否一致。对比时需要统一这些口径；软件名称相同不保证默认值完全相同。

## 如何控制内存

读取时显式提供 `indexers`；BC 可以配置 `work_dir` 使用磁盘映射，并在用完后 `close_result`。复用 Regridder，按需控制时间块与空间块。EOF 仍会对传入矩阵进行完整稠密分解，减少 n_modes 只截取结果，不是稀疏求解。

## 为什么输出文件已存在会失败

`Field.to_netcdf` 使用独占创建，避免覆盖已有结果。为新实验选择新的输出路径。不同文件流程的输出策略见各章节，不应假设所有接口都自动覆盖。

## 如何报告问题

在 GitHub Issue 中提供软件版本、操作系统、`backend_info()`、最小可复现代码、完整错误和输入维度/单位/日历。不要上传访问令牌、私有数据或受限原始资料。可以构造小型合成 Field 复现问题。
