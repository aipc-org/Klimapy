# Klimapy 对照 CDO / ESMValTool 的功能缺口与路线图

实现进度：已完成第一批日数据接口，见[使用说明](../statistics/series.md)和[验收记录](series-pipeline-2026-10-30.md)。下文为对照调研，月资料权重和显式面积评分也已接入，见[后续验收](weighted-statistics-2026-10-30.md)；CF 时间边界、QC 和顺序配置也已接入，见[工作流验收](recipes-qc-bounds-2026-10-30.md)；完整路线图仍有通量积分、集合评估和缓存恢复等未实现项。

调研日期：2026-10-30。依据：当前本地源码、CDO 与 ESMValTool/ESMValCore 官方文档，辅以 xclim、xESMF、xsdba。本文是功能与设计调研，未安装这些工具做全项数值或速度认证，也没有据此新增运行依赖。

## 1. 建议先补什么

当前优先补足通用数据流程与评估能力：**多文件流式处理 → 时间聚合与元数据 → 模式评估 → 可复现配置 → 多模式集合**。在此基础上再扩展气候诊断与影响指标。

已有的 27 项 ETCCDI 对应入口、faer SVD/EOF、降水 BCSD、日尺度气候态、规则经纬网格重映射、NetCDF 与区域掩膜值得继续完善。不能因为没有对方同名函数就判为缺失，也不能因为已有一个同名入口就认定功能、日历和数值口径完全相同。

## 2. 比较对象的侧重点

| 对象 | 值得借鉴的能力 | Klimapy 的对应方向 |
| --- | --- | --- |
| CDO | 文件算子、时间/空间统计、集合处理、命令组合 | 把常用处理做成有明确内存与时间语义的文件到文件流程 |
| ESMValCore | 数据预处理、数据描述、权重与 recipe 配置 | 统一多资料的单位、坐标、时间、区域与运行记录 |
| ESMValTool | 研究诊断、模式评估与结果展示 | 增加可重复执行的评估与诊断工作流 |
| xclim | 气候影响指标及其科学参数约定 | 先扩展热浪、干旱和事件描述，而非简单堆积别名 |
| xESMF | 广泛网格类型、地理重映射及掩膜语义 | 扩展当前一维经纬网格能力，验证覆盖与守恒 |
| xsdba | 校正方法、训练/应用流程 | 补温度、变化信号保持及独立验证 |

依据：[CDO 功能目录](https://mpim-sw.gitlab-pages.dkrz.de/cdo/modules/index.html)、[ESMValCore 预处理](https://docs.esmvaltool.org/projects/ESMValCore/en/latest/recipe/preprocessor.html)、[ESMValTool 评估示例](https://docs.esmvaltool.org/en/latest/recipes/recipe_perfmetrics.html)、[xclim](https://xclim.readthedocs.io/en/stable/indices.html)、[xESMF](https://xesmf.readthedocs.io/en/stable/why.html)、[xsdba](https://xsdba.readthedocs.io/en/stable/)。

这些是能力参考，不代表应把对方整个框架加入生产依赖。保持 Python 元数据接口 + NumPy + Rust 内核；外部工具优先用于独立参考验证。

| 优先级 | 能力 | 状态 | 本地核查结论 |
| --- | --- | --- | --- |
| P0 | 多文件目录、合并与流式算子 | 部分已有 | 单文件 Dataset/read_field、部分 BCSD/气候态分块已存在；缺通用多文件集合和文件到文件算子链。 |
| P0 | 日/月/季/年聚合、距平与比较期选择 | 部分已有 | 已有多日历、日序、缺测质量控制和日数据气候态；缺通用时间重采样、季节和月资料时间权重。 |

| P0 | 可复现任务配置与来源链 | 部分已有 | 已有 BCSD jobs 成败报告和 MCP；不是任意分析 DAG、缓存或断点恢复。 |

## 4. 第一组：多文件与有界内存处理

### 当前情况

`Field` 是已载入 NumPy 的数组，只有一维维度坐标。`read_field` 面向单文件；`Dataset` 可按块读写。气候态和 BCSD 已有分块处理，但不存在可覆盖通用分析的多文件集合与算子链。ETCCDI 的空间分块也不能消除已经加载的完整输入数组。

### 建议补充

- 建立本地数据目录，识别变量、模式、实验、成员、网格、频率和时间范围。
- 多文件按实际时间排序、联合读取或合并写出；报告重叠、重复和缺口，默认不静默丢弃。
- 选择变量、日期、层次和区域后，再按需读取；支持选择计划的预检查。
- 支持时间块之间传递状态：滑动累计和连续事件跨文件边界也必须一致。
- 提供“文件集合 → 处理 → 新文件”的入口，约束同时打开的文件数与峰值内存。

CDO 的 `merge` 与 `mergetime` 分别面向字段合并和时间合并，说明这两类任务应分开设计；其文档也指出打开文件数受系统限制。[官方说明](https://mpim-sw.gitlab-pages.dkrz.de/cdo/modules/man/Merge.html)。Klimapy 应定义自己的冲突和句柄策略，而非仅拼接文件名。

**验收重点：** 多文件结果与单一合并文件一致，输入顺序不影响结果；冲突策略、跨年/跨文件窗口及内存上限有独立测试。

## 5. 第二组：时间、元数据与质量控制

### 时间算子

已有日历解码、逐日有效性检查和按有效日计算的气候态，不应重做一遍。缺少的是通用的日/月/季/年聚合、季节距平、比较期选择和月资料处理。

建议增加：月/季/年平均与累计、任意月份组合、DJF 与跨年季节、滑动统计、明确参考期的距平与标准化距平。必须区分状态量平均、通量按时间积分、已累计量求和；月资料转年/季平均应使用时间边界或月长，不能一律等权。

### 元数据与空间权重

保留 time bounds、网格 bounds、辅助二维坐标、面积字段、`cell_methods` 与 `cell_measures`。当前 Field 的“一维坐标对应一个维度”不能完整表示这些内容，需要先设计扩展的数据模型，再承诺通用网格。

区域面积平均应允许真实 cell area 和覆盖分数。现有 `cos(lat)` 权重可继续用于适当规则网格，但不是任意网格的真实面积积分。参考框架已经区分时间间隔与网格面积权重。[ESMValCore 权重说明](https://docs.esmvaltool.org/projects/ESMValCore/en/latest/recipe/preprocessor.html#weighted-statistics)。

建议统一导出 QC JSON：时间缺口、变量单位、覆盖率、负降水或异常温度、默认单位假设、掩膜与修复记录。范围阈值应可配置；数据修复必须显式、可追踪，不静默改变观测事实。

**验收重点：** 360_day/闰年与 DJF 边界；月资料按真实时间长度加权；单位积分保持量纲；元数据往返不会丢失关键边界。

## 6. 第三组：模式评估与统计推断

建议新增统一评估模块，先做配对偏差、MAE、RMSE、相关系数、标准差比、中心化 RMSE、空间型相关，以及季节循环和变化量的误差。

每项明确：时间与空间共同域、配对缺测、面积权重、有效样本数、零方差和分母。泰勒图与评估矩阵使用这些经过验证的数值，不应先画图再拼定义。可参考 ESMValTool 的模式评估与 Taylor 展示。[官方评估 recipe](https://docs.esmvaltool.org/en/latest/recipes/recipe_perfmetrics.html)。

统计推断作为独立下一步：趋势和相关的置信区间、自相关敏感性、块 bootstrap、Mann–Kendall/Theil–Sen 与场检验 FDR。不要默认逐格点的 p<0.05 就是整个场显著。每种方法都需说明假设和适用条件。

**验收重点：** 有已知解的偏差/相关样本、不相关与有自相关序列、缺测配对、零方差；独立参考与科学假设一起记录。

## 7. 第四组：多模式集合

当前 `process_models` 为逐模式 BCSD jobs 的成功/失败管理，不是集合统计。建议新增：

- 多模式/成员均值、中位数、分位带、标准差与有效模式数。
- 共同时间和共同网格、缺测模式处理、模式/成员维度分离。
- 历史—未来差值或相对变化及符号一致率。
- 显式选择每成员等权、每模式等权或用户给定权重，避免成员多的模式自动占主导。

CDO 提供集合统计算子，可作为基本功能和数值对照对象。[Ensstat 文档](https://mpim-sw.gitlab-pages.dkrz.de/cdo/modules/man/Ensstat.html)。不把集合分位区间直接标为统计置信区间，也不把所有成员视为独立样本。

**验收重点：** 成员数量不平衡、缺失模式、不同时间覆盖、权重归一化、实际有效模式数和变化符号一致率。

## 8. 第五组：可复现任务配置

借鉴 ESMValTool recipe 对数据、预处理与诊断的组织，但不必复制其整套配置格式。[Recipe 定义](https://docs.esmvaltool.org/projects/ESMValCore/en/latest/recipe/overview.html)。

建议先提供标准库即可读取的 JSON 配置，包含数据源、变量、区域、基准期、步骤、输出与科学参数。每次运行保存输入指纹、配置、软件与算法版本、网格、单位、随机状态、父子产物关系和错误；已有 batch 成败日志可作为基础。[ESMValCore 输出组织](https://docs.esmvaltool.org/projects/ESMValCore/en/latest/quickstart/output.html)。

缓存与断点续跑只有在输入和参数指纹都匹配时才能复用；不能因为同名输出已存在就跳过。先实现小范围、确定性的流水线，再加入更复杂的 DAG 与并行调度。已有 MCP 入口可以复用同一任务规范，但 AI 不是数值正确性的替代品。

**验收重点：** 相同配置可复现；修改基准期或输入后缓存失效；中断恢复不产生半成品冒充有效输出；来源链能追到输入与参数。

## 9. 专项扩展：哪些值得做，哪些应后置

### 重映射

已有多种一维经纬网格方法。先补经度周期接缝、海陆/无效格点掩膜、覆盖分数及权重保存/复用，再做二维曲线网格、矢量旋转或非结构网格。xESMF 对曲线网格和掩膜的处理说明这些是独立能力，不是把插值公式换一个名字就能获得。[网格说明](https://xesmf.readthedocs.io/en/stable/why.html)、[掩膜说明](https://xesmf.readthedocs.io/en/stable/notebooks/Masking.html)。

覆盖不足时的归一化、缺测传播与质量守恒要分别定义。部分覆盖重归一化不能被写成全域质量必然守恒。

### 校正与降尺度

优先补温度校正、训练/验证期隔离、留年交叉验证与校正前后评估，再考虑 QDM 等变化信号保持方法。对降水与温度分别明确乘法/加法口径、湿日频率、尾部外推、TX≥TN 和非负降水。参考 xsdba 的训练/应用结构与算法实现，但不把现有分位数映射自动称为已经保持未来变化信号。[官方库](https://xsdba.readthedocs.io/en/stable/)、[算法源码](https://github.com/Ouranosinc/xsdba/blob/main/src/xsdba/adjustment.py)。

### 极端与影响指标

27 项核心指标对应入口已有，优先做通用事件表：起止、持续、强度、阈值和跨年分配。再补热浪、SPI、多尺度干旱与复合干热事件；SPEI 还需要明确 PET 和水分平衡方案。分布函数并不等于参数拟合器，WSDI 也不等于所有热浪定义。[xclim 指标目录](https://xclim.readthedocs.io/en/stable/indices.html)。

查阅 ESMValTool 的诊断时需辨认当前与 legacy recipe；例如调研时其 latest 目录包含 legacy SPEI 入口，不能照搬旧 recipe 就宣称符合当前版本。[Recipe 目录](https://docs.esmvaltool.org/en/latest/recipes/index.html)。

### 环流与多格式

ENSO/Niño3.4、遥相关和环流指标可利用已有 EOF，但仍需单独定义区域、变量、层次、去趋势、参考期与滤波。压力/混合层垂直插值、风矢量旋转、GRIB/eccodes 和 Zarr 作为 P2；在已有 NetCDF 降水/温度工作流完善前不一次性引入所有原生库。

## 10. 建议的实施批次

| 批次 | 实施内容 | 可以完整交付的研究任务 |
| --- | --- | --- |
| A | 多文件集合、基础时间聚合、必要元数据和 QC | 多年逐文件资料 → 可靠月/季/年统计 |
| B | 通用评估指标与真实面积权重 | 模式—观测的区域、空间与季节评估 |
| C | 最小任务 JSON、来源记录、批处理与集合统计 | 一份配置完成多模式比较并导出可追踪结果 |
| D | 校正独立验证、温度校正、事件与干旱 | 验证校正收益并开展影响分析 |
| E | 更复杂网格、环流/垂直层与多格式 | 按新数据和研究问题扩展 |

A 中的数据与元数据设计应先确定；其余可以按已有接口拆分实施。P0 不代表必须一次提交全部实现，更不建议此时做无边界的“大一统 climate framework”。
